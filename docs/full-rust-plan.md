# Full Rust Minarbot migration

Issue [#57](https://github.com/labsiqbal/minarbot/issues/57) · Baseline `c5de099` (0.16.4) · 2026-11-22

**Use Leptos CSR for the web app, Tauri 2 for the desktop shell after packaged parity, and Tokio/reqwest for HTTP integration tests. Keep Playwright as the external browser test harness.** Ship one route group at a time behind a server-side selector. Keep Electron and its update feed available until packaged Tauri upgrades pass on each supported OS. Use [#58](https://github.com/labsiqbal/minarbot/issues/58) for the release tooling port.

## Status

[#67](https://github.com/labsiqbal/minarbot/issues/67) retired the React app,
hosted React bundle, client selector, and Node Hub after Leptos became default
and screenshot and Hub contract coverage moved forward. The owner approved a
direct Leptos-only cutover on 2026-11-23. The phase plan below records the
original rollout. Current [build and recovery](../crates/web/README.md) and
[coverage](test-ledger.md#67-ui-coverage-ledger) live with Leptos. Electron
remains packaged pending the #66 Tauri matrix.

Leptos and Dioxus both compose normal HTML and work with Axum's JSON and SSE APIs. Leptos CSR fits this deployment because it updates DOM nodes directly, its typed web elements expose DOM refs, and Axum can serve the same-origin assets without running another server or reconciling a virtual DOM. Dioxus has React-like component ergonomics and a credible web renderer. Prefer Leptos for initial delivery, with Dioxus as fallback if the real kit or route pilot misses the gates below. Dioxus desktop would still require a separate update and trust-policy solution. Yew is a viable CSR alternative with a virtual DOM and direct browser APIs. Sycamore has a direct reactive DOM, and native egui/Iced would require a different accessibility, text, iframe and CSS implementation. Both candidates ship stable release series before 1.0. Pin the framework and WASM tools and re-run the kit and protocol tests on upgrades. ## Desktop decision

Use Tauri 2 (MIT OR Apache-2.0) over a direct WRY/Tao shell. Tauri supplies an integration point for packaging, permissions, single instance and signed desktop updates while Axum keeps serving the same application. WRY alone leaves packaging, updater, plugin policy and application menus to Minarbot. Native WebView engines reduce bundled Chromium dependencies and introduce platform-specific rendering and permission behavior. Test Linux WebKitGTK plus AppImage on fresh Linux with target libraries, Windows WebView2/NSIS with WSL 2, and macOS WKWebView/DMG on each shipped architecture. Establish supported OS/webview versions in the packaged pilot. [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/) · [WRY](https://github.com/tauri-apps/wry)

## Test and release decisions

- **Rust HTTP integration tests.** Reuse the binary-spawning pattern from `crates/minarbot-server/tests/browser_pairing.rs` and `browser_computer.rs`. Run the built production binary via `CARGO_BIN_EXE_minarbot-server`, test config on stdin, loopback port 0, a private temp SQLite/config root, bounded readiness, and RAII child teardown. Use Tokio, reqwest and the workspace's existing HTTP/SSE/WS clients. Build fixtures in-process on loopback using Axum and migrate bridge behavior in `app/rust-*-test-bridge.ts` only as tests need it. Run restart, lost response, retries and concurrent callers against real persisted state. Keep fixture tokens and auth stubs out of production. Keep opt-in external suites opt-in.
- **Measure coverage by behavior.** Assign IDs or source test names for each Node case. Compare status/body/schema, event order and data invariants side by side before removing a Node test. Carry SQLite migration and signed-update fixtures, auth/tenant and origin checks, connector/token redaction, exact submission/revision replay, partial streams, and browser interactions into the ledger. Port pure UI algorithms as unit tests with their Rust call sites. Keep app build/lint/resource and provenance checks until their replacements enforce equivalent rules.
- **Keep Playwright.** It already provides user-facing role locators, screenshots, route/fault interception, frame and WebSocket support, actual Chromium, and the suite used by current feature agents. Chromiumoxide is CDP-only and would require recreating Playwright's locator/retry and browser lifecycle conventions. Fantoccini supports W3C WebDriver across browsers given installed drivers, but needs additional code for the existing request/WS fixture controls and screenshot workflows. Keep Playwright Chromium as the release gate. Add Playwright WebKit coverage for highest-risk journeys and a packaged WebView matrix for Linux, Windows and macOS. Let measured Playwright maintenance cost determine any later runner change. [Playwright locators](https://playwright.dev/docs/locators) · [Chromiumoxide](https://github.com/mattsse/chromiumoxide) · [Fantoccini](https://github.com/jonhoo/fantoccini)
- **Reuse #58 for xtask.** Start the escape-hatch command while the product is still hybrid, preserving CLI flag behavior, branch-claim ancestry checks, release notes/version, dry run, signed runtime and image manifests, archive layout, desktop assets/feeds, CI artifact signing, resource/environment gates, and retry of publish from a staged release. Compare same-commit manifests, archived path/mode/content tables and signatures using a fixture key. Remove Node release wrappers together with their callers after the signed dry-run/install/rollback check. Migrate `desktop/scripts/build.mjs` on the Tauri lane and move the version source only after all installers and gates read the same release metadata. Keep current release jobs until shadow output proves parity.

### Original release rules and ownership

- Use one release build with separate client asset namespaces and an explicit route owner. Route transfers use normal same-origin navigation. Keep public paths, deep links, API and settings keys stable. Keep React as default while Leptos is selectable in test and pilot. Avoid embedding two SPAs or loading two clients on a route. If a route group shares draft, stream or tab state, switch the group together. Transfer a route only after the compatible state and fallback check.
- Keep SQLite and versioning independent of the frontend change. Deploy both clients against one compatible API. If an in-flight feature changes an API additively, land the contract and React smoke first or coordinate transfer directly with its single route owner. For rollback, switch the route selector to the previous asset set with current data. Verify draft and uncertain-command journals across versions, including clearing/cancel behavior under valid user control. Avoid a retry that replays a mutation on UI rollback.
- **#41** owns goal/loop in React until chip/inspector/Stop/Needs-you and routines/calendar tests land. Capture typed command and status fixtures once. Port them with phases 4 and 5. **#49** owns the HTML frame routes, CSP, tool contract and bridge. Consume the merged fixture and smoke in phase 4. **#48** owns Memory UI and its mutation/undo and search contracts. Port the final settings panel in phase 5. **#50/#51** own schemas, native renderer behavior and frame/approval contracts. If either starts after the conversation route transfers, implement the UI in Leptos once, plus matching fixture and Playwright coverage. **#52** owns installation, signature verification and approval integration in Rust. Build its settings screen once in whichever client owns the route at issue start, then transfer the saved contract if needed. Record route ownership and dependency milestones in the issue ledger at each release cut. [#41](https://github.com/labsiqbal/minarbot/issues/41) · [#48](https://github.com/labsiqbal/minarbot/issues/48) · [#49](https://github.com/labsiqbal/minarbot/issues/49) · [#50](https://github.com/labsiqbal/minarbot/issues/50) · [#51](https://github.com/labsiqbal/minarbot/issues/51) · [#52](https://github.com/labsiqbal/minarbot/issues/52)
- Require green existing lint, build, Rust/Node tests and unweakened Playwright journeys for both implementations of the transferred route. Capture and review dark/light at desktop and narrow widths, keyboard focus return, screen-reader names/live status, errors/loading/empty states, reload and deep links. Compare HTTP, SSE/WS, console, CSP and cleanup receipts. Confirm zero unintended provider calls, duplicate sends or dropped drafts. Treat failed security, replay and update checks as cutover blockers.
- In phase 1, publish cold and warm TTI/transfer baselines for a fixture route at the same browser, CPU and network settings, using multiple runs and medians/p95. Require gzip and immutable hashed WASM, no blank screen after injected failed fetch, and warm navigation and stream UI p95 within 10% of measured React baseline on that route. Use a provisional cold-start budget of React p95 + 20% and record any approved exception. Measure both release build wall time and component rebuild separately from slot wait and network. Keep existing server resource budgets. Review startup and size again before making client default.

### Risks that affect release order

| Risk | Gate |
| --- | --- |
| Startup regression and offline asset mismatch | Axum serves the selected HTML with matching hashed assets. Test lost initial WASM fetch and warm reload before migrating another route. |
| Duplicate sends, lost drafts or cross-conversation events | Preserve command IDs, storage format and scope. Inject response loss and stale snapshots while changing routes and rolling back. |
| Keyboard regression in kit or rich replies | Test focus restoration, logical order, typeahead and screen-reader announcements in real panels. Test rich frame messages and approval on current browser and desktop engines. |
| Desktop feed or OS signing breaks upgrade | Keep legacy feed alongside Tauri updater. Stage with fixture keys and prove previous-to-new and new-to-next upgrades per OS. |
| Unmapped Node service or test remains | Audit release contents and running entrypoints up front. Block dependency removal on a completed consumer and coverage inventory. |
