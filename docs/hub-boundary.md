# Hub and canonical runtime boundary

Inventory at `3874c65` for #65. The hosted hub and canonical workspace API have separate listeners, databases and trust boundaries. `crates/minarbot-server/src/computer/hub.rs` is the outbound member-node client. The hosted process accepts project traffic and coordinates work on independently owned member nodes.

Run the Rust hosted listener with `minarbot-server --hub` and an explicit `MINARBOT_HUB_CONFIG` JSON file. It binds loopback and owns a separate marked SQLite database. See the runtime and fixture notes below before switching an existing hub.

The P1-A through P1-D entries in the owner's local backlog document the coordination-only pilot, verified identity and host handoff, signed member link and dual consent, and the integrated browser flow. The hosted pilot stayed disabled on the owner instance. Real identity setup, TLS/WSS, operations, native per-effect fencing and production rollout remain separate gates. The fixture contract covers both browser and node roles.

## Rust implementation

- `crates/minarbot-server/src/hub.rs` and `hub/` own exact browser and node host routing, pinned Clerk JWKS and synthetic fixture identity, durable host-only sessions, one-use handoff, project/member/invite authority, node enrollment and renewal, signed WebSocket replay, dual consent, grant snapshots, chat, SSE, and per-effect leases. It uses the original checksummed hub migration and extension table layout. The Rust listeners take the same writer lock. Workspace and canonical launchers reject hosted data.
- `crates/minarbot-server/src/computer/hub.rs` remains the outbound member client and execution boundary. It verifies bounded, duplicate-free signed responses for HTTP and WebSocket. The hosted listener coordinates work. Local policy and action approval stay on each member node.
- `crates/web/src/hub.rs` and `crates/web/src/hub/` implement the hosted UI with the same routes, presentation and draft keys. Set `MINARBOT_APPEARANCE_CLIENT=leptos` after packaging both clients to stage Leptos. React is the default and `?ui=react` selects rollback.

### Start and maintain

Use the existing Node config keys. Provide `domain`, `accountsHost` as `accounts.<domain>`, `dataPath`, `mailboxKeyPath`, and `identity`. `identity.mode=clerk` requires `issuer` and a pinned public `jwksPath` with an optional `audience`. Use `mode=stub` with `tokensPath` only in fixtures. Both resolve already admitted accounts. The verifier makes zero identity network calls. `web.distPath` serves the packaged `app/dist/hub` entrypoint and its independent asset manifest. `nodeLink.signingKeyPath` accepts an Ed25519 PKCS#8 private key. Terminate TLS at the operator proxy and preserve exact HTTPS host headers. Only explicitly trusted browser proxy addresses may send `X-Forwarded-Host`.

With the listener stopped, use the same config for `minarbot-server --hub admit ISSUER SUBJECT` and `minarbot-server --hub account-status ID active|blocked`. `minarbot-server --hub backup PATH` writes a new private snapshot. Point a separate config at the restore copy, then run `minarbot-server --hub fence-restore`. Inspect that copy before running `minarbot-server --hub activate GENERATION` with the returned recovery generation. Restore holds pending invitations, invalidates sessions and leases, and marks unfinished effects unknown. Off-host snapshot encryption and stale-writer-lock recovery are operator tasks.

## Owner decisions before removal

- The Rust hosted listener is the only supported Hub runtime. Once the Rust listener passes the same data, identity, enrollment, grant, replay and chat fixtures, rehearse a stopped-writer cutover on a private copy of the hub database and retain the old binary/config for rollback. Delete the Node entrypoint only after the owner confirms the hosted deployment and rollback window.
- Keep the unmounted Node authority helpers `transferOwner`, `archiveSection`, and `deleteProject`. Their repository callers are the authority fixtures, with no hosted HTTP route or shipped CLI. If operator scripts consume these exports, port the same revision and tombstone semantics before removing the helpers.
- Keep the React hub Vite build and app route selection until dual-client browser parity and release rollback have been verified. Then remove it together with the live selector fallback under #67.
- Confirm the hosted identity plan. Existing browser sign-in accepts explicit development fixture tokens and continues an existing session. Production Clerk login UI and provider configuration were left pending in P1-B/P1-D. Keep pinned JWT verification and the handoff contract. A production operator must configure the provider and verify the HTTPS pilot before exposing it.
- Confirm whether the Pi extension and Cloudflare Worker remain host-specific JavaScript adapters. A Rust Pi migration needs matching tool approval, registry and cancellation hooks in Pi. A Worker replacement needs matching raw mail, signed endpoint, retry and rejection fixtures before DNS or routing changes. Keep both entrypoints for existing consumers.
- Review the unused Clerk React, Node keyring and Anthropic SDK dependencies and npm CLI aliases after checking downstream source-tree/package consumers. Keep the TS protocol harness until the Rust coverage ledger matches it. Keep the non-Node shared-data worker outside this issue's retirement decision.
